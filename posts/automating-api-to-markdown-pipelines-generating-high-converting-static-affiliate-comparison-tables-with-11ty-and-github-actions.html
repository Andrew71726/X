Automating API-to-Markdown Pipelines: Generating High-Converting Static Affiliate Comparison Tables with 11ty and GitHub Actions

Build a zero-cost programmatic static affiliate site. Automate API-to-Markdown pipelines using 11ty and GitHub Actions to generate high-converting product tables.

AM
Alex Mercer
12 min read • Niche Researcher

The Performance and Monetization Crisis in Modern Affiliate Marketing

For over a decade, database-driven Content Management Systems (CMS) like WordPress have been the default infrastructure for affiliate marketing. However, this architectural reliance on runtime database queries, heavy plugins, and dynamic page rendering introduces severe performance degradation. According to a landmark study on web performance published in the ACM Digital Library, page load latency directly correlates with user abandonment and decreased conversion rates (Souders, 2009). Every additional 100 milliseconds of latency can reduce conversion rates by up to 7%.

In the competitive landscape of affiliate marketing, where high-converting comparison tables are critical for driving click-through rates (CTR), runtime database overhead is a liability. Traditional affiliate plugins query product prices, features, and affiliate links from local databases or external APIs on every single page view. This increases Time to First Byte (TTFB), triggers Cumulative Layout Shift (CLS) when dynamic widgets render late, and exposes the system to security vulnerabilities.

To bypass these limitations, modern SEO architects are shifting toward a programmatic static site generator monetization model. By transitioning from dynamic runtime rendering to a build-time api to markdown pipeline, publishers can generate blisteringly fast, secure, and highly optimized static affiliate comparison tables. Using 11ty (Eleventy) as the static site generator and GitHub Actions as the CI/CD engine, developers can construct a low cost programmatic affiliate builder that scales to tens of thousands of pages for virtually zero hosting cost.

The Architecture of a GitOps-Driven Programmatic Affiliate Builder

An automated API-to-Markdown pipeline relies on a Git-as-a-Database pattern. Instead of querying a live SQL database when a user visits a page, data is fetched during the build process, transformed into structured Markdown files with rich YAML front matter, and compiled into optimized static HTML. 

[External APIs] 
       │ (Price, Specs, Stock, Affiliate Links)
       ▼
[GitHub Actions Runner] (Scheduled Cron / Webhook Event)
       │
       ├─► Runs Node.js Data Ingestion Script
       ├─► Transforms JSON to Markdown Front Matter (.md)
       ├─► Commits New/Updated Markdown Files to Git Repository
       ▼
[Eleventy (11ty) Compiler]
       │
       ├─► Parses Markdown & YAML front matter
       ├─► Renders Static Semantic HTML Tables & JSON-LD Schema
       ▼
[Global CDN (Cloudflare Pages / Netlify)]

This architecture offers three distinct advantages: 1. Sub-100ms Page Loads: Pre-rendered HTML is served directly from the edge of global CDNs, maximizing Core Web Vitals metrics, which Google uses as ranking signals (Google Search Quality, 2024). 2. Zero Run-Time API Dependencies: If an merchant API goes down, the site remains fully functional using the last successfully built static data, preventing broken links and lost revenue. 3. Serverless Economics: By leveraging GitHub Actions free tiers and static hosting platforms like Cloudflare Pages, hosting costs remain $0 even when serving millions of monthly impressions.

Step 1: Building the API Ingestion Script (fetch-products.js)

The foundation of the pipeline is a Node.js script that queries product data from external APIs (such as Amazon PA-API, ShareASale, or a proprietary JSON feed), normalizes the schema, and generates clean Markdown files with YAML front matter.

Save the following script as scripts/fetch-products.js in your project root. This script fetches data, validates the response, and writes standard Markdown files to your 11ty content directory.

const fs = require('fs');
const path = require('path');
const axios = require('axios');
const jsYaml = require('js-yaml');

// Configuration
const API_ENDPOINT = 'https://api.mockmerchant.com/v1/products';
const OUTPUT_DIR = path.join(__dirname, '../src/products');

// Ensure output directory exists
if (!fs.existsSync(OUTPUT_DIR)) {
  fs.mkdirSync(OUTPUT_DIR, { recursive: true });
}

async function fetchAffiliateData() {
  try {
    console.log('Initiating API data fetch...');
    const response = await axios.get(API_ENDPOINT, {
      headers: { 'Authorization': `Bearer ${process.env.MERCHANT_API_KEY}` }
    });

    const products = response.data.products;
    if (!Array.isArray(products)) {
      throw new Error('Invalid API response format: Products array not found.');
    }

    console.log(`Successfully fetched ${products.length} products. Commencing transformation...`);

    products.forEach(product => {
      // Normalize and sanitize product properties
      const frontMatter = {
        title: product.name,
        sku: product.sku,
        price: parseFloat(product.price),
        currency: product.currency || 'USD',
        rating: parseFloat(product.rating) || 4.5,
        affiliateUrl: product.affiliate_link,
        imageUrl: product.image_url,
        features: product.key_features || [],
        pros: product.pros || [],
        cons: product.cons || [],
        lastUpdated: new Date().toISOString(),
        category: product.category
      };

      // Generate body content for the product page
      const markdownContent = `---
${jsYaml.dump(frontMatter)}---

### Product Overview
${product.description || 'No description provided.'}
`;

      const fileName = `${product.sku.toLowerCase().replace(/[^a-z0-9]/g, '-')}.md`;
      fs.writeFileSync(path.join(OUTPUT_DIR, fileName), markdownContent, 'utf-8');
    });

    console.log('API-to-Markdown pipeline execution completed successfully.');
  } catch (error) {
    console.error('Pipeline execution failed:', error.message);
    process.exit(1);
  }
}

fetchAffiliateData();

Step 2: Configuring Eleventy for High-Converting Comparison Tables

Once the Markdown files are populated, Eleventy compiles them into semantic, accessible, and high-converting comparison tables. Unlike dynamic JavaScript-based tables that trigger layout shifts, our static tables are rendered as pure HTML table elements, styled with utility-first CSS, and enriched with structured JSON-LD data.

First, create a template file at src/index.njk to render the comparison table using Nunjucks:

---
layout: base.njk
title: "Top Recommended Products in 2024"
---

<div class="comparison-table-container">
  <table class="affiliate-comparison-table">
    <thead>
      <tr>
        <th>Product Image</th>
        <th>Product Details</th>
        <th>Key Features</th>
        <th>Rating</th>
        <th>Price</th>
        <th>Action</th>
      </tr>
    </thead>
    <tbody>
      {% for product in collections.products | sortByPrice %}
      <tr class="product-row" data-price="{{ product.data.price }}">
        <td class="col-image">
          <img src="{{ product.data.imageUrl }}" alt="{{ product.data.title }}" loading="lazy" width="120" height="120">
        </td>
        <td class="col-details">
          <h3>{{ product.data.title }}</h3>
          <p class="sku-text">SKU: {{ product.data.sku }}</p>
        </td>
        <td class="col-features">
          <ul>
            {% for feature in product.data.features | limit(3) %}
            <li>{{ feature }}</li>
            {% endfor %}
          </ul>
        </td>

            Check Price

      </tr>
      {% endfor %}
    </tbody>
  </table>
</div>

{# Structured JSON-LD Product Schema #}
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "ItemList",
  "name": "{{ title }}",

        }

To make this template work seamlessly, register a custom collection and a sorting filter in your .eleventy.js configuration file:

const moment = require('moment');

module.exports = function(eleventyConfig) {
  // Create a collection of products from the Markdown files
  eleventyConfig.addCollection("products", function(collectionApi) {
    return collectionApi.getFilteredByGlob("src/products/*.md");
  });

  // Sort filter: High to Low Price
  eleventyConfig.addFilter("sortByPrice", function(values) {
    return values.slice().sort((a, b) => b.data.price - a.data.price);
  });

  // Limit filter for rendering lists
  eleventyConfig.addFilter("limit", function(arr, limit) {
    return arr.slice(0, limit);
  });

  // Human-readable date filter
  eleventyConfig.addFilter("dateFilter", function(date) {
    return moment(date).format('MMM DD, YYYY');
  });

  return {
    dir: {
      input: "src",
      output: "dist"
    }
  };
};

Step 3: Automating the Pipeline with GitHub Actions

To ensure your product tables contain accurate, up-to-date prices, stock statuses, and links, you must automate the data-fetching and build cycle. GitHub Actions acts as the orchestrator, running on a chronological schedule (cron job) to fetch data, commit updates back to the repository, and trigger a static deployment.

Create a workflow configuration file at .github/workflows/update-affiliates.yml:

name: Scheduled API-to-Markdown Pipeline

on:
  schedule:
    # Runs every day at 00:00 UTC
    - cron: '0 0 * * *'
  workflow_dispatch: # Allows manual trigger within GitHub UI

permissions:
  contents: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v3
        with:
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Run API-to-Markdown Pipeline Script
        env:
          MERCHANT_API_KEY: ${{ secrets.MERCHANT_API_KEY }}
        run: node scripts/fetch-products.js

      - name: Check for Changes
        id: git-check
        run: |
          git diff --exit-code || echo "changes_detected=true" >> $GITHUB_OUTPUT

      - name: Commit and Push Updated Markdown Content
        if: steps.git-check.outputs.changes_detected == 'true'
        run: |
          git config --global user.name "GitHub Actions Automation"
          git config --global user.email "actions@github.com"
          git add src/products/*.md
          git commit -m "chore(data): automated daily product update [skip ci]"
          git push origin main

      - name: Deploy Static Site
        if: steps.git-check.outputs.changes_detected == 'true'
        run: npm run build

Note on configuration: The [skip ci] flag in the commit message prevents recursive action triggers, ensuring the workflow terminates cleanly after committing the newly updated Markdown data.

Search Engine Quality Guidelines and Structured Data Optimization

In December 2021, Google rolled out its Product Reviews Update, transforming the evaluation criteria for affiliate websites. Google's Search Quality Rater Guidelines explicitly state that affiliate content must go beyond "thin aggregation" of product descriptions (Google, 2024). Sites that simply reproduce specifications from Amazon or other e-commerce platforms without adding unique synthesis, quantitative performance data, or structured comparisons are filtered out of the index.

An automated, high-performing api to markdown pipeline satisfies these strict guidelines through several programmatic strategies:

  1. Semantic Comparison Matrix: By organizing products dynamically into arrays (e.g., listing pros, cons, and specific metrics), the resulting layout provides a structured comparative synthesis, helping users make informed purchase decisions quickly.
  2. Explicit Schema Validation: The inline JSON-LD Schema generated in our 11ty template explicitly provides search engine crawlers with verified values for Product, Offer, price, and availability. This structural clarity often results in search engine rich snippets, significantly boosting organic Click-Through-Rates (CTR).
  3. Crawl Efficiency and Freshness: Search engines prioritize websites that maintain accurate pricing and offer fast crawling speeds. By utilizing a 11ty github actions affiliate automation workflow, search engines crawl highly optimized static HTML, leading to faster indexing cycles and improved keyword coverage.

By ensuring a zero-layout-shift experience, static tables maximize user retention. Because your affiliate comparison tables compile directly to static HTML, visitors on slow mobile connections experience instantaneous interactivity, drastically reducing cart abandonment rates.

Conclusion & Next Steps

Automating an api to markdown pipeline using 11ty and GitHub Actions represents the modern gold standard for programmatic affiliate site construction. It solves the performance and security overhead associated with traditional content management systems while keeping hosting costs at zero.

To scale this model further: 1. Integrate multiple affiliate networks to dynamically display the cheapest purchasing option for your users. 2. Use Tailwind CSS to optimize the comparison table's responsiveness across mobile viewports. 3. Implement automated end-to-end tests (such as Playwright) in your GitHub Actions workflow to ensure no broken links or empty table elements are published to production.
