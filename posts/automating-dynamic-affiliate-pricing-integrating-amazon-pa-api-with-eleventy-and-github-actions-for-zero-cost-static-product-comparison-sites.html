Automating Dynamic Affiliate Pricing: Integrating Amazon PA-API with Eleventy and GitHub Actions for Zero-Cost Static Product Comparison Sites

Learn how to build a high-performance, zero-cost static product comparison site using Eleventy, Amazon PA-API v5, and automated GitHub Actions workflows.

AM
Alex Mercer
12 min read • Niche Researcher

In the highly competitive landscape of programmatic SEO and affiliate marketing, website performance and data accuracy are critical vectors for search engine visibility and conversion rate optimization. Traditional dynamic systems—such as WordPress coupled with heavy relational database queries—frequently suffer from high Time to First Byte (TTFB), security vulnerabilities, and substantial hosting overhead.

Conversely, static site generators (SSGs) like Eleventy offer unmatched speed, security, and hosting efficiency. However, deploying a static infrastructure presents a major challenge for affiliate marketers: maintaining real-time pricing and compliance with affiliate network policies. The Amazon Associates Program Operating Agreement strictly mandates that pricing displayed on a site must be accurate and updated regularly, typically within a 24-hour window, accompanied by an explicit timestamp.

This article outlines a production-grade, zero-cost architecture that solves this dilemma. By integrating the Amazon Product Advertising API (PA-API v5) directly into the build pipeline of an Eleventy static site, automated by GitHub Actions cron triggers, you can build a programmatic static product comparison engine that maintains compliance, loads instantly, and runs entirely on free-tier static hosting.

The Architecture of Dynamic-Static Hybridization

To achieve both maximum speed and pricing compliance, we decouple the data retrieval layer from the presentation layer. Instead of querying the Amazon PA-API on every client-side page load (which exposes API credentials and degrades client-side performance), or querying a database on every server-side request (which introduces latency), we query the API during the static site compilation phase.

+-----------------------+         +-----------------------+         +-------------------------+
| GitHub Actions Cron   | ------> | Node.js Fetch Script  | ------> | Amazon PA-API v5        |
| (Runs every 6 hours)  |         | (AWS Signature v4)    | <------ | (Real-time Price Data)  |
+-----------------------+         +-----------------------+         +-------------------------+
                                              |
                                              v Writes to
+-----------------------+         +-----------------------+         +-------------------------+
| Deployment Target     | <------ | Eleventy Build Engine | <------ | local JSON Data Files   |
| (Cloudflare Pages/S3) |         | (Compiles HTML)       |         | (src/_data/products.json)|
+-----------------------+         +-----------------------+         +-------------------------+

This workflow runs on a scheduled cron job via GitHub Actions (e.g., every 6 hours). The workflow executes a Node.js script that authenticates with the Amazon PA-API, pulls the latest pricing, availability, and product metadata, and saves this information to a local JSON file within Eleventy's global data directory (src/_data/). Eleventy then compiles the site into optimized HTML and deploys the static files to a global Content Delivery Network (CDN) like Cloudflare Pages or GitHub Pages.

Compliance, Performance, and Search Intent

This architectural pattern is strongly supported by industry data and academic research on search engine optimization and user behavior:

  1. Core Web Vitals and Conversion Rates: A study by Google on mobile page speed found that as page load time goes from 1 second to 3 seconds, the probability of bounce increases by 32% (Google, 2018). Furthermore, research in the ACM Transactions on the Web demonstrates that system latency directly correlates with decreased user queries and lower overall engagement (Anurag & Claypool, 2020). By serving pre-rendered HTML, this Eleventy architecture achieves a sub-100ms TTFB, maximizing user retention and conversion.
  2. Google's Helpful Content System: Google's Search Quality Rater Guidelines emphasize the need for high-effort, original content and reliable data on affiliate sites (Google, 2024). Sites that display outdated prices or broken links are classified as "low-quality affiliate template sites." Automated static site pricing updates guarantee that search engine crawlers always index accurate information, signaling high editorial standards.
  3. Amazon PA-API Compliance: Section 4 of the Amazon Associates Product Description and Pricing policy states that product price and availability must be updated regularly. If cached, this data cannot be stored for more than 24 hours. Our automated compilation process ensures that prices are refreshed multiple times daily, writing the exact compilation date next to the pricing block to ensure total compliance.

Step-by-Step Technical Implementation

1. Constructing the Node.js PA-API Fetch Script

To communicate with Amazon's PA-API v5, requests must be signed using AWS Signature Version 4. While Amazon provides an official SDK, we can implement a highly optimized, lightweight integration script utilizing the official @amazon/paapi5-node-sdk package or a custom fetch module.

Create a file named scripts/fetch-prices.js in the root of your Eleventy project. This script takes an array of Amazon Standard Identification Numbers (ASINs), queries the API, and outputs a structured JSON file to src/_data/amazonProducts.json.

// scripts/fetch-prices.js
const fs = require('fs');
const path = require('path');
const ProductAdvertisingAPIv5 = require('paapi5-nodejs-sdk');

// Initialize Amazon PA-API Credentials from environment variables
const defaultClient = ProductAdvertisingAPIv5.ApiClient.instance;
defaultClient.accessKey = process.env.AWS_ACCESS_KEY_ID;
defaultClient.secretKey = process.env.AWS_SECRET_ACCESS_KEY;
defaultClient.host = 'webservices.amazon.com'; // Change based on your locale
defaultClient.region = 'us-east-1';

const apiInstance = new ProductAdvertisingAPIv5.DefaultApi();

// Define the list of ASINs to track
const asins = ['B09G96T27G', 'B09G9FPGTN', 'B09G9D8KRZ']; // Example ASINs

const getItemsRequest = new ProductAdvertisingAPIv5.GetItemsRequest();
getItemsRequest['PartnerId'] = process.env.AMAZON_ASSOCIATE_TAG;
getItemsRequest['PartnerType'] = 'Associates';
getItemsRequest['Marketplace'] = 'www.amazon.com';
getItemsRequest['ItemIds'] = asins;
getItemsRequest['Resources'] = [
  'Images.Primary.Large',
  'ItemInfo.Title',
  'Offers.Listings.Price'
];

apiInstance.getItems(getItemsRequest, (error, data, response) => {
  if (error) {
    console.error('Error calling PA-API v5:', error);
    process.exit(1);
  } else {
    try {
      const responseObj = ProductAdvertisingAPIv5.GetItemsResponse.constructFromObject(data);
      const results = {};

      if (responseObj.SearchResult && responseObj.SearchResult.Items) {
        responseObj.SearchResult.Items.forEach(item => {
          const asin = item.ASIN;
          const title = item.ItemInfo.Title.DisplayValue;
          const imageUrl = item.Images.Primary.Large.URL;
          const offer = item.Offers && item.Offers.Listings ? item.Offers.Listings[0] : null;
          const price = offer ? offer.Price.DisplayAmount : 'N/A';
          const isAvailable = offer ? offer.Availability.Type === 'Now' : false;

          results[asin] = {
            asin,
            title,
            imageUrl,
            price,
            isAvailable,
            lastUpdated: new Date().toISOString()
          };
        });
      }

      // Output path for Eleventy global data
      const outputPath = path.join(__dirname, '../src/_data/amazonProducts.json');
      fs.writeFileSync(outputPath, JSON.stringify(results, null, 2));
      console.log(`Successfully updated data for ${Object.keys(results).length} products.`);
    } catch (parseError) {
      console.error('Failed to parse API response:', parseError);
      process.exit(1);
    }
  }
});

2. Templating with Eleventy

Once the script runs, Eleventy reads src/_data/amazonProducts.json and makes it globally accessible within template files under the amazonProducts variable.

Below is an example of a programmatic static product comparison component written in Nunjucks (src/_includes/components/comparison-card.njk). It features the product image, live pricing, affiliate link structure, and the mandatory Amazon API disclosure with a dynamic timestamp.

{# src/_includes/components/comparison-card.njk #}
{% set product = amazonProducts[asin] %}

{% if product %}
<div class="product-card border p-6 rounded-lg shadow-md my-4 flex flex-col md:flex-row items-center">
  <div class="w-full md:w-1/3 flex justify-center mb-4 md:mb-0">
    <img src="{{ product.imageUrl }}" alt="{{ product.title }}" class="max-h-48 object-contain" loading="lazy">
  </div>
  <div class="w-full md:w-2/3 md:pl-6 flex flex-col justify-between">
    <div>
      <h3 class="text-xl font-bold mb-2 text-gray-800">{{ product.title }}</h3>
      <p class="text-sm text-gray-500 mb-4">ASIN: <span class="font-mono">{{ product.asin }}</span></p>
    </div>

      <div class="price-info">
        <span class="text-2xl font-extrabold text-green-600">{{ product.price }}</span>

          <time datetime="{{ product.lastUpdated }}" class="font-medium">
            {{ product.lastUpdated | dateFilter }}
          </time>

    </div>
  </div>
</div>
{% else %}

Note: Implement a custom filter (e.g., dateFilter) in your .eleventy.js configurations to format the raw ISO date string into an easily readable format like MMM DD, YYYY HH:mm UTC.

3. Automating with GitHub Actions

To satisfy Amazon's strict compliance policies, we use a GitHub Actions workflow to query the API and rebuild the site automatically every 6 hours.

Create the file .github/workflows/rebuild.yml:

name: Scheduled Static Site Price Update

on:
  schedule:
    # Run every 6 hours (00:00, 06:00, 12:00, 18:00 UTC)
    - cron: '0 */6 * * *'
  workflow_dispatch: # Allows manual trigger within GitHub UI
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup Node.js Environment
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Fetch Latest Pricing from Amazon PA-API
        run: node scripts/fetch-prices.js
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          AMAZON_ASSOCIATE_TAG: ${{ secrets.AMAZON_ASSOCIATE_TAG }}

      - name: Build Eleventy Static Site
        run: npm run build

      - name: Deploy to Cloudflare Pages
        uses: cloudflare/pages-action@v1
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          projectName: 'your-eleventy-comparison-site'
          directory: '_site'
          gitBranch: 'main'

For security, make sure to add AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AMAZON_ASSOCIATE_TAG, CLOUDFLARE_API_TOKEN, and CLOUDFLARE_ACCOUNT_ID to your GitHub Repository Secrets.

Optimizing Search Performance with JSON-LD Schema

To ensure search engines fully understand your comparison table and render Rich Snippets (such as star ratings, pricing ranges, and stock status directly in search results), you should inject a structured Product Schema alongside your static HTML markup.

{
  "@context": "https://schema.org/",
  "@type": "Product",
  "name": "Example Affiliate Product Group",
  "description": "In-depth static comparison of top-tier consumer products.",
  "offers": {
    "@type": "AggregateOffer",
    "priceCurrency": "USD",
    "lowPrice": "199.99",
    "highPrice": "299.99",
    "offerCount": "3",
    "offers": [
      {
        "@type": "Offer",
        "price": "199.99",
        "priceCurrency": "USD",
        "url": "https://www.amazon.com/dp/B09G96T27G/?tag=YOUR_ASSOCIATE_TAG_HERE",
        "itemCondition": "https://schema.org/NewCondition",
        "availability": "https://schema.org/InStock"
      }
    ]
  }
}

Integrating this structured metadata directly into your Eleventy collection templates allows search engine crawlers to immediately extract precise, up-to-date structured information without executing heavy client-side JavaScript.

Conclusion and Operational Economics

Building dynamic affiliate comparison sites using a static-dynamic hybrid architecture represents a massive shift in affiliate site monetization strategy. By moving data aggregation to the build phase, you completely eliminate database hosting fees, minimize security vulnerabilities, and achieve Core Web Vital metrics that are nearly impossible to match on standard, database-driven setups.

With zero-cost hosting tiers from platforms like Cloudflare Pages and GitHub Actions' free execution minutes, you can run a vast, programmatic network of affiliate sites at virtually zero operational cost. This ensures your margins remain exceptionally high while delivering a lightning-fast, compliant, and highly converting user experience.
